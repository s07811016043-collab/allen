搜索与文案生成效果度量台

面向 AI NAS 影视/音乐搜索与文案生成场景的离线评估工具：上传标注集与系统输出，在浏览器本地完成指标计算与可视化（数据不出本机）。

这套度量在测什么

两类任务，两套指标。搜索效果回答"用户输入查询后，正确的结果有没有排在前面"；文案生成效果回答"模型生成的文字是否相关、通顺、准确、有吸引力"。两者都需要一份人工标注的黄金数据作为对照基准——没有标注就没有度量。

搜索效果指标（本页自动计算）

指标回答的问题计算方式适用场景
Hit@K（Top-K 命中率）前 K 条结果里至少有 1 条相关结果的查询占比命中查询数 / 总查询数语义类查询的验收主指标（如"剧情搜索 Top5 命中率 ≥ 80%"）
MRR@K（平均倒数排名）第一条相关结果平均排在第几位mean(1 / 首个相关结果的排名)衡量"正确答案是否够靠前"，适合片名/演员等精确检索
Recall@K（召回率）标注的相关结果中有多少被找回来了前K中相关结果数 / 标注相关结果总数衡量漏召回，适合"把某系列都找出来"类查询
Precision@K（精确率）前 K 条结果里有多少是相关的前K中相关结果数 / K衡量误召回（结构化硬条件场景应接近 1）
NDCG@K（归一化折损累计增益）综合考虑相关程度分级与排序位置的总分DCG@K / 理想DCG@K，增益取标注等级(0–3)有分级标注（非常相关/相关/部分相关）时最全面的排序质量指标

验收口径建议（对应需求评估文档）

结构化查询（年份/评分/演员/国家）看 Top1 准确率与硬条件满足率；剧情/情绪等语义查询看 Hit@5；组合查询看 NDCG@5。不要用"能检索出合适结果"这类不可测的表述。

文案生成效果指标（本页自动计算）

指标回答的问题计算方式说明
维度均分相关性/流畅性/准确性/吸引力各多少分各维度 1–5 分打分的平均值打分来自人工标注或 LLM 评审（LLM-as-a-Judge），评分标准见"操作步骤"页的评审提示词模板
通过率多少比例的样本达到发布标准所有维度 ≥ 阈值(默认4分) 的样本占比作为上线验收的硬指标，阈值可在页面调整
ROUGE-L（字符级）生成文案与参考文案的最长公共子序列重合度F1 = 2PR/(P+R)，基于字符 LCS仅当提供参考文案（reference 列）时计算；适合摘要类任务，推荐语类文案以主观维度为准
低分样本（badcase）哪些样本拖了后腿按总分升序列出badcase 回流是迭代提示词/模型的主要输入

结果怎么读

① 所有指标都是 0–1（或 1–5 分），越高越好；② 单一系统的绝对分数意义有限，对比才有意义——对比两个版本（v1/v2）、对比不同查询类别（剧情类 vs 年份类），找出短板；③ 语义类指标是概率性的，关注趋势与 badcase 收敛，而不是追求 100%。

任务必须提供怎么来

② 标注集 qrels：每条查询哪些结果是相关的、相关程度几级
③ 被测系统的检索结果 run：每条查询返回的 Top-N 及排序		查询集从需求文档示例 + 真实用户查询日志抽样；标注由产品/运营对照曲库/片库人工标（每条查询标 2–5 个相关项，10 分钟/条以内）；run 由研发跑一遍检索接口导出

② 模型生成结果
③ 各维度评分（人工或 LLM 评审）
④ 参考文案（可选，摘要类建议提供）		评分推荐用下方 LLM 评审提示词批量打分 + 人工抽检 20% 校准；参考文案可取自现有运营文案或人工撰写

搜索效果度量 · 操作步骤

准备标注集 qrels.csv

三列：query_id（查询编号）、doc_id（曲目/影片在系统中的 ID）、relevance（0=不相关 1=部分相关 2=相关 3=非常相关）。没标注的 doc 默认视为不相关，不用写。

query_id,doc_id,relevance
q01,m01a,3
q01,m01b,2

导出被测系统结果 run.csv

研发对评测查询集逐条调用检索接口，取 Top-10 写入：system（版本名，可多版本对比）、query_id、doc_id、rank（从 1 开始；也可给 score，按分数降序）。

system,query_id,doc_id,rank,score
v2_混合检索,q01,m01a,1,0.93

（可选）准备 queries.csv 启用类别分析

三列：query_id、query_text、category（剧情语义/主观偏好/组合条件/演员/年份…）。提供后可看到分类别对比图，直接定位短板。

上传 → 选 K → 计算

在"搜索效果度量"页上传文件，K 按验收口径选（语义类建议 5，精确类建议 1），点击计算。所有计算在浏览器本地完成。

读结果 → 回流迭代

先看指标汇总是否达验收线，再看类别对比找短板，最后逐条过 badcase 清单：未命中的是召回问题（查词典/索引），命中但排名靠后的是排序问题（调权重）。导出明细 CSV 附在测试报告里。

文案生成度量 · 操作步骤

准备评测用例并跑生成

每类文案（歌单推荐语/影片命中理由/简介摘要）准备 20+ 条 prompt，跑被测模型得到 generated 列。

用 LLM 评审批量打分（或人工打分）

将下方提示词与每条样本一起发给评审模型（建议用比被测模型更强的模型），得到四个维度 1–5 分。务必人工抽检 20% 对齐评分标准。

你是文案质量评审。针对【任务要求】和【生成文案】，按以下四个维度独立打分（1-5 整数），只输出 JSON：
- relevance 相关性：文案是否切合任务要求与对象（歌单/影片）本身
- fluency 流畅性：是否通顺自然、无语病、符合中文表达习惯
- accuracy 准确性：事实是否正确（人名/情节/风格），有无编造
- attractiveness 吸引力：是否具体、有记忆点，避免"精彩好看"式空话
任务要求：{prompt}
生成文案：{generated}
（如有参考文案可对照：{reference}）
输出：{"relevance":?,"fluency":?,"accuracy":?,"attractiveness":?,"reason":"一句话"}

汇总成 gen_results.csv

固定列：case_id、category、prompt、generated、reference（可选）；其后每个数值列都会被识别为一个评分维度（列名即维度名）。

上传 → 设阈值 → 计算

在"文案生成度量"页上传，通过阈值默认 4 分（每个维度都 ≥ 4 才算通过），可按发布标准调整。

读结果 → 优化提示词/模型

最弱维度决定优化方向：准确性低 → 给模型补充结构化元数据；吸引力低 → 在提示词中加入风格范例（few-shot）；按类别图定位哪类文案需要单独的提示词模板。

与开源框架配合（进阶）

样本量大或要进 CI 时，用命令行框架算分，本页做可视化与归档：

# 搜索指标（Python, ranx）：与本页算法一致，可交叉验证
pip install ranx
python -c "
from ranx import Qrels, Run, evaluate
qrels = Qrels.from_file('qrels.trec')  # 或 from_df 读 CSV
run   = Run.from_file('run.trec')
print(evaluate(qrels, run, ['hit_rate@5','mrr@5','recall@5','ndcg@5']))"

# 生成质量（DeepEval）：内置 G-Eval / 幻觉 / 摘要指标，评审模型可换国产或本地模型
pip install deepeval
deepeval test run test_copywriting.py

# 提示词 A/B 回归（promptfoo）：自带 Web UI，适合提示词版本对比
npx promptfoo@latest eval && npx promptfoo@latest view

框架产出的逐样本分数整理成上述 CSV 上传本页即可，形成统一的评估报告出口。

本度量网页的技术栈及选择理由

选型理由
Vue 3（github.com/vuejs/core）当前国内团队最主流的前端框架之一；本页用其"全局构建版"直接 <script> 引入，零构建、零 Node 依赖，克隆仓库双击 index.html 即可运行——与 NAS 团队"离线、轻部署"的约束一致。相比 React 免去 JSX 编译链，相比原生 JS 保留声明式数据绑定的可维护性。
Apache ECharts（github.com/apache/echarts）Apache 顶级项目、国内可视化事实标准，中文文档完善；柱状图/直方图/分组对比开箱即用，支持按主题重绘（本页亮/暗切换即依赖此能力）。
纯静态 + 浏览器本地计算评测数据（查询日志、标注、生成文案）可能含内部信息，本页所有解析与指标计算都在浏览器内完成，不发起任何网络请求——与产品"数据不出域"的卖点同一原则；依赖（vue/echarts）已随仓库离线内置于 vendor/。
指标算法自实现（约 100 行）Hit/MRR/Recall/Precision/NDCG 与 ROUGE-L 均为标准公式，JS 直接实现并可与 ranx 交叉验证，避免为网页引入 Python 后端。
