搜索与文案生成效果度量台

上传标注集与系统输出，在本机完成指标计算与可视化 · 数据不出本机

这套度量在测什么

搜索效果回答"用户输入查询后，正确的结果有没有排在前面"；文案生成效果回答"模型生成的文字是否相关、通顺、准确、有吸引力"。两者都需要一份人工标注的黄金数据作为对照基准。所有指标的计算口径与主流开源评估框架对齐，每个指标都标注了出处，便于与命令行工具交叉验证。

搜索效果指标 口径：ranx / trec_eval

与 ranx（github.com/AmenRa/ranx）、trec_eval（pytrec_eval）的同名指标口径一致，可用 ranx.evaluate(qrels, run, ["hit_rate@5","mrr@5","map@5","ndcg@5"]) 交叉验证。

指标来源框架回答的问题计算方式适用场景
Hit@K（命中率）ranx: hit_rate前 K 条里至少有 1 条相关结果的查询占比命中查询数 / 总查询数语义类查询验收主指标（如"剧情搜索 Hit@5 ≥ 80%"）
MRR@K（平均倒数排名）ranx / trec_eval: recip_rank第一条相关结果平均排第几mean(1 / 首个相关结果排名)片名/演员等精确检索"是否够靠前"
MAP@K（平均精确率均值）ranx / trec_eval: map综合考虑所有相关结果的位置mean(每命中一条相关结果时的 Precision 的平均)多相关结果查询的综合排序质量
Recall@K（召回率）ranx: recall标注的相关结果被找回多少前K中相关数 / 标注相关总数"把某系列都找出来"类查询的漏召回
Precision@K（精确率）ranx / trec_eval: P前 K 条里有多少是相关的前K中相关数 / K误召回（结构化硬条件场景应接近 1）
F1@Kranx: f1精确与召回的调和平均2PR / (P + R)需要单一数字平衡查准/查全时
NDCG@Kranx / trec_eval: ndcg考虑相关程度分级与位置的总分DCG@K / 理想DCG@K，增益取标注等级(0–3)有分级标注时最全面的排序质量指标
R-Precisionranx / trec_eval: r_prec前 R 条（R=该查询相关总数）里的精确率前R中相关数 / R不受 K 选取影响的平衡指标

验收口径建议

结构化查询（年份/评分/演员/国家）看 Top1 命中（K=1 的 Hit）与 Precision；剧情/情绪等语义查询看 Hit@5；组合查询看 NDCG@5。避免"能检索出合适结果"这类不可测表述。

文案生成效果指标

指标来源框架回答的问题计算方式说明
维度均分G-Eval · DeepEval相关性/流畅性/准确性/吸引力各几分各维度 1–5 分的平均值打分来自人工或 LLM 评审（LLM-as-a-Judge），方法与 DeepEval 的 G-Eval 指标一致；提示词模板见"操作步骤"页
通过率DeepEval: pass rate多少样本达到发布标准所有维度 ≥ 阈值(默认4) 的样本占比对应 DeepEval 测试用例的通过率概念，作为上线门禁
ROUGE-1 / 2 / Lrouge-score（Google）与参考文案的 n-gram / 最长公共子序列重合度字符级 F1（中文按字切分）需提供 reference 列；适合摘要类，推荐语类以主观维度为准
Distinct-1 / 2通用多样性指标（Li et al.）生成文案的用词多样性全部生成文本中不重复 n-gram 占比过低说明模型在"套模板"，各条文案雷同
Badcase 清单通用实践哪些样本拖了后腿按总分升序列出badcase 回流是迭代提示词/模型的主要输入

结果怎么读

① 搜索指标为 0–1、评分维度为 1–5，越高越好；② 单一系统的绝对分数意义有限，对比才有意义——对比版本（v1/v2）、对比查询类别，找出短板；③ 语义类指标是概率性的，关注趋势与 badcase 收敛，而不是追求 100%。

① 提供数据

推荐先下载 Excel 模板（含填写说明与示例），填好后整个文件拖进来即可；也支持任意列名的 Excel/CSV——系统会自动识别关键信息，缺什么会告诉你怎么补。

搜索效果度量 · 操作步骤

下载并填写 Excel 模板（推荐）

在"搜索效果度量"页下载模板，含 3 张表（qrels标注集 / run检索结果 / queries查询清单）与填写说明，示例行替换成真实数据即可。也可以上传自己现成的 Excel/CSV——列名支持中文别名（查询ID/文档ID/相关性/排名/系统…），缺关键列时页面会明确提示补什么。

标注 qrels

relevance 相关等级：0=不相关 1=部分相关 2=相关 3=非常相关；未标注的结果默认不相关，无需填写。

导出被测系统结果 run

研发对评测查询集逐条调用检索接口，取 Top-10 写入；system 列填版本名，填多个版本自动对比。

拖入文件 → 选 K → 计算

K 按验收口径选（语义类建议 5，精确类建议 1）。所有计算在浏览器本地完成。

读结果 → 回流迭代

先看指标是否达验收线，再看类别对比找短板，最后逐条过 badcase：未命中是召回问题（查词典/索引），命中但靠后是排序问题（调权重）。导出明细附进测试报告。

文案生成度量 · 操作步骤

下载模板 / 准备评测用例并跑生成

每类文案（歌单推荐语/影片命中理由/简介摘要）准备 20+ 条 prompt，跑被测模型得到生成文案。

用 LLM 评审批量打分（或人工打分）

将下方提示词与每条样本发给评审模型（建议比被测模型更强），得到四个维度 1–5 分。务必人工抽检 20% 对齐评分标准。此方法即 DeepEval 的 G-Eval 指标做法。

你是文案质量评审。针对【任务要求】和【生成文案】，按以下四个维度独立打分（1-5 整数），只输出 JSON：
- relevance 相关性：文案是否切合任务要求与对象（歌单/影片）本身
- fluency 流畅性：是否通顺自然、无语病、符合中文表达习惯
- accuracy 准确性：事实是否正确（人名/情节/风格），有无编造
- attractiveness 吸引力：是否具体、有记忆点，避免"精彩好看"式空话
任务要求：{prompt}
生成文案：{generated}
（如有参考文案可对照：{reference}）
输出：{"relevance":?,"fluency":?,"accuracy":?,"attractiveness":?,"reason":"一句话"}

填入模板 → 拖入上传 → 设阈值 → 计算

通过阈值默认 4 分（每个维度都 ≥ 4 才算通过），可按发布标准调整。

读结果 → 优化提示词/模型

最弱维度决定优化方向：准确性低 → 给模型补充结构化元数据；吸引力低 → 提示词加风格范例（few-shot）；按类别图定位哪类文案需要单独模板。

与开源框架配合（进阶）

样本量大或要进 CI 时，用命令行框架算分（口径与本页一致），本页做可视化与归档：

# 搜索指标（ranx）—— 与本页同口径，可交叉验证
pip install ranx
python -c "
from ranx import Qrels, Run, evaluate
qrels = Qrels.from_file('qrels.trec')
run   = Run.from_file('run.trec')
print(evaluate(qrels, run, ['hit_rate@5','mrr@5','map@5','recall@5','precision@5','f1@5','ndcg@5','r-precision']))"

# 生成质量（DeepEval，G-Eval 口径）
pip install deepeval
deepeval test run test_copywriting.py
