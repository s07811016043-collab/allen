# AI 功能 PRD 章节模板

按需取用。迭代型 PRD 可只保留 1、2、6、7、8 章。

## 1. 背景与用户问题

- 目标用户:
- 触发场景:
- 现状与痛点(用户现在怎么解决,成本是什么):
- 为什么现在做(时机):

## 2. 目标与非目标

- 本期目标(可验证的表述,如"X 场景下首次生成采纳率 ≥ N%"):
- 明确不做(Non-goals):
- 成功指标(北极星 + 护栏指标):

## 3. 功能能力边界

| 维度 | 内容 |
|---|---|
| 保证做好 | 例:中文商品图的主体描述 |
| 尽力而为 | 例:多主体复杂场景 |
| 明确不支持 | 例:医疗影像;需在交互中告知用户 |
| 做不好时的表现 | 例:描述遗漏细节,而非编造事实 |

## 4. 交互流程与兜底策略

- 主流程:
- 模型输出错误/低质量时:用户如何发现、如何纠正(重新生成/手动编辑/一键反馈)
- 超时/服务不可用时:降级方案(缓存结果/规则兜底/隐藏入口)
- 用户不满意时:反馈入口与数据回流方式

## 5. 数据需求

- 评测数据:来源、数量、标注方式
- 优化数据(prompt 示例/微调):来源与合规确认
- 线上回流:采集哪些字段、脱敏要求

## 6. 评测与验收标准(必填)

- 样例集:__ 条,来源:__,覆盖场景:__
- 指标与阈值:

| 指标 | 定义 | 阈值 | 评测方式 |
|---|---|---|---|
| 例:事实错误率 | 输出中含编造事实的比例 | ≤ 2% | 人工双标 |
| 例:P95 延迟 | 请求到首字返回 | ≤ 3s | 自动 |

- 未达标处理:阻塞上线 / 缩小灰度范围 / 记录风险由谁拍板

## 7. 发布计划

- 灰度策略(范围、时长、放量条件):
- 上线后观测指标与看板:
- 回滚条件(触发什么数字就回滚):

## 8. 风险与开放问题

- 已知风险与缓解:
- 待决策项(负责人 + 截止时间):
