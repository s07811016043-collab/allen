# AI 竞品功能拆解

## 任务分流

1. **单品深拆**:深入拆一个竞品的某个 AI 功能 → 走默认工作流。
2. **多品横评**:多个竞品同一能力对比 → 先定统一的对比维度和测试输入,所有竞品用同一套输入测试,再填表对比。
3. **快讯解读**:竞品刚发布了新功能,要快速判断 → 压缩为三问:它解决什么问题、对我们的用户有没有替代性、我们要不要跟进(跟进/观察/不跟,给理由)。

## 开始之前必须确认的信息

1. 拆解目的是什么(决定要不要跟进?找差异化定位?给老板汇报?)——目的决定详略
2. 能不能实际使用竞品(可实测的结论和只看公开资料的结论,可信度必须分开标注)
3. 对比基准是谁(我们的哪个功能/版本)

## 默认工作流

1. **先定用户任务,再看功能**。明确竞品这个功能服务于用户的什么任务(Job to be done),后续所有对比都围绕"谁把这个任务完成得更好",而不是功能数量。
2. **实测优先**。能实测就构造 5~10 组典型输入(含边界输入)实际跑,记录输出质量、延迟、失败时的表现。不能实测时,收集官方材料、用户评价、演示视频,并给每条信息标注来源与可信度。
3. **按四层拆解**:
   - 交互层:入口在哪、触发方式、结果如何呈现、用户如何纠错
   - 能力层:实际质量如何、能力边界在哪、兜底怎么做
   - 数据层:它靠什么数据变好、有没有数据飞轮
   - 商业层:免费/付费界线、成本结构推测、和主产品的关系
4. **推断设计意图**。对关键设计问一句"它为什么这么做",区分"做不到"和"故意不做"——这往往是最有价值的判断,但必须标注为推断。
5. **落到我方动作**。结论必须回答:对我们的威胁/机会是什么、建议跟进/观察/不跟、如果跟进最小验证方案是什么。

## 产出格式

- 一页结论(威胁等级、核心差异、建议动作)
- 四层拆解明细
- 实测记录(输入、输出、观察),或资料来源清单
- 明确区分:事实(实测/官方)、转述(用户评价/媒体)、推断(自己的判断)

## 产出前自查清单

- [ ] 有实测记录,或明确说明了为何无法实测
- [ ] 每个结论能区分事实、转述、推断
- [ ] 拆解落到了"我们该怎么办",而不是停在"它做了什么"
- [ ] 没有出现"功能强大""体验优秀"这类无信息量的评价

## 边界

- 只使用公开渠道信息和正常使用产品获得的观察,不涉及任何非公开信息获取
- 跟进决策需要的可行性评估交给 `ai-feature-feasibility`
- 决定跟进后的需求撰写交给 `ai-prd-author`
