# 评测指标设计清单与常见陷阱

## 生成类任务的常用维度拆解

| 维度 | 典型定义 | 常用评测方式 |
|---|---|---|
| 事实准确性 | 输出内容与输入/事实一致,无编造 | 人工双标;大模型评审需校准 |
| 完整性 | 关键信息覆盖率(先定义"关键信息"清单) | 按要点清单打分 |
| 相关性 | 输出是否切题、无冗余 | 大模型评审 + 抽样人评 |
| 表达质量 | 通顺、符合语言风格要求 | 大模型评审 |
| 安全合规 | 无违规、无敏感信息泄漏 | 规则 + 安全模型 + 人工抽检 |
| 格式正确性 | 结构化输出可解析、字段齐全 | 自动校验(优先做,成本最低) |

## 打分制式选择

- **二元判定**(合格/不合格):标注一致性最高,适合事实错误、格式错误这类硬伤。
- **3~5 档评分**:适合表达质量这类连续维度;必须为每一档写锚定示例,否则一致性会很差。
- **对比评测**(A/B 哪个好):适合模型选型;注意位置偏差,A/B 顺序要随机化。

## 常见陷阱

1. **只有平均分,没有分布**。平均 4.2 分可能藏着 5% 的严重错误。严重错误(事实编造、安全问题)要单独统计比率,不能被均分稀释。
2. **样例集被调优污染**。用来改 prompt 的样例不能再用来验收,封闭集必须隔离。
3. **大模型评审未校准就当真值**。先抽 50~100 条人工标注,算与模型评审的一致率,达不到约定水平(如 85%)就不能替代人工。
4. **指标好看但用户不买账**。离线指标必须与至少一个线上行为指标(采纳率、编辑率、重试率、负反馈率)建立对应关系,定期核对。
5. **只测常规场景**。样例集中边界输入(超长、空白、多语言、对抗性输入)应占一定比例,建议不低于 20%。
6. **阈值凭感觉拍**。新功能没有历史数据时,用竞品水平或人类基准作为参照,并注明阈值是初始值、首次灰度后修订。

## 线上监控的最小集合

- 自动指标:请求量、成功率、P95 延迟、格式错误率
- 质量代理指标:采纳率、编辑距离、重新生成率、负反馈率
- 人工抽检:固定频率(如每周)抽样评审,与离线维度使用同一套打分标准
- 告警:严重错误类指标设阈值告警,并约定响应人
