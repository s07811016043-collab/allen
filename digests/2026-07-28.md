### 6. MCP 协议今日定稿 2026-07-28 规范：传输层彻底「无状态化」，Extensions 升为一等公民

Model Context Protocol 于 7 月 28 日定稿新规范，为发布以来最大改动。SEP-2575 移除 initialize 握手、SEP-2567 移除 Mcp-Session-Id 头与协议级会话，使 MCP 在传输层完全无状态——任意请求可命中任意服务器实例，远程 MCP 服务器可直接跑在普通轮询负载均衡后。Extensions 升为独立版本化机制（reverse-DNS 标识），新增 MCP Apps（沙箱 iframe 服务端渲染 UI）与 Tasks（长任务句柄轮询），六项 SEP 将 MCP 服务器定位为 OAuth 2.1 资源服务器，并首次引入正式弃用政策。RC 早在 5/21 锁定，留出约 10 周验证窗。

> **金句摘录**：「协议现在是无状态的：没有握手、没有 session id，任意请求都能命中任意服务器实例。」——@dsp_（MCP 维护者）

## 三、对我们的意义（IMPACT）

**K3 把「开源前沿模型 + 端侧全栈」从口号变成了可复制的工程范式，这是家庭 AI 底座级的一天。** 它不只开源权重，还一次性放出专家并行通信库、KDA 高性能算子、智能体 RL 沙箱三层基建，甚至演示了模型自主设计 45nm 推理芯片——等于把「训练→推理→硬件」的开源链条补全。华为昇腾、阿里超节点 day-0 跑通近 3 万亿参数，意味着「不依赖英伟达也能自托管前沿能力」不再是 PPT。对我们的直接价值不是部署 594GB 的 K3 本体，而是它开源的 FlashKDA 算子和量化感知训练范式——这正是端侧小模型「既要小又要准、又要在国产芯片上跑」的关键拼图，值得立刻拉下来评估。

**MCP 今日「无状态化」定稿，是给家庭 Agent 基础设施的一份及时规范。** 移除握手与 session id、让任意请求命中任意实例，意味着家庭助手连接的本地工具/设备网关可以像普通 Web 服务一样水平扩展、失败即重试，不必维护脆弱的长连接会话；新引入的 OAuth 2.1 资源服务器定位与正式弃用政策，恰好对上我们一直强调的「权限边界 + 可回滚」。同日英伟达牵头的 Open Secure AI Alliance 开源 NOOA 框架，把身份、权限、隔离、护栏、日志、审计做成全 agent 栈的开放标准——这几乎是我们「可信家庭 AI」清单的逐条对照，值得直接跟进其身份（SPIFFE/SPIRE）与可追溯（trace/audit）方案。建议把设备接入层直接对齐 2026-07-28 MCP 规范，安全层参考 NOOA，别在旧的有状态会话模型上再投入。

**资本市场用一天的暴跌替我们把「算力叙事」重新定价——便宜、可自托管的智能才是护城河，而非堆算力。** K3 开源令美股存储普跌、英伟达兜底 OpenAI 引爆「循环融资」担忧、纳德拉亲口警示泡沫，三件事同日发生，指向同一判断：靠资本和电力堆出来的算力优势正在被开源效率侵蚀。对做家庭 AI 的我们是利好——竞争的重心正从「谁买得起最多 GPU」转向「谁能把小模型在本地做得又快又可信」，而后者恰是端侧路线的主场。

## 四、今日 AI 精选（DEEP DIVES）

**1.《MCP 2026-07-28 规范：为什么要让协议彻底无状态》（MCP 官方博客）**
核心问题：MCP 为何要动到握手和会话这两块地基。方案：SEP-2575/2567 移除 initialize 与 Mcp-Session-Id，让远程服务器可跑在普通轮询负载均衡后；Extensions 升为独立版本化机制，新增 MCP Apps（沙箱 UI）与 Tasks（长任务轮询），并把服务器定位为 OAuth 2.1 资源服务器。可借鉴：家庭助手的设备/工具网关应按「无状态 + 短任务句柄轮询」重构，长任务用 Tasks 而非维持长连接——这对时断时续的家庭网络环境尤其关键。[阅读原文](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

**2.《Kimi K3 权重上线次日：Unsloth Dynamic 2.0 GGUF 量化实录》（Hugging Face 社区）**
核心问题：一个 MXFP4 原生、用 KDA 线性注意力的万亿模型，社区怎么把它塞进本地。方案：Unsloth 用 Dynamic 2.0 按层重要性做非均匀量化（重要层留更高精度），但踩到坑——llama.cpp/vLLM 必须先补 KDA 支持、标准 prefix caching 不适用。可借鉴：这印证了「训练内量化 vs 事后量化」的方法论差异，也提醒我们端侧上线新架构模型时，推理框架的算子支持往往比权重本身更是瓶颈。[阅读原文](https://huggingface.co/unsloth/Kimi-K3-GGUF)

**3.《K3 实测：它赢在哪、输在哪》（The Decoder）**
核心问题：一个登顶前端榜的开源模型，能力到底均不均衡。论证：Frontend Code Arena 第一、SWE-bench 93.4%，但 FrontierMath Tier 4 仅 39%、幻觉率约 51%；作者结论是 K3「在对 agent 开发者最要紧的赛道以三分之一价格取胜」。可借鉴：选端侧/自托管模型不能只看综合指数——要按自己的真实任务（家庭场景更接近「前端生成 + 工具调用」而非「专家级数学」）挑长板模型，并对幻觉率单独设防。[阅读原文](https://the-decoder.com/moonshots-kimi-k3-outperforms-fable-5-in-frontend-code-but-lags-far-behind-in-complex-math/)
